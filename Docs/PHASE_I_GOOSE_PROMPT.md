# Goose Agent Prompt — Phase I: Email-First Communications Center + Compliant Campaign Foundation

> Phases A through H are complete. MCA King now has activity/tasks, lender offer isolation, funded deals + broker revenue + internal sales rep commissions, merchant-file submissions, search/saved views, account settings/admin user management, renewals, reporting/analytics, and compliance/audit hardening. Phase I should add a communications center, but it must be **email-first** and **SMS-future-ready only**. Do not build live SMS sending in this phase.

---

## Business Model Rules — Read Before Writing Anything

MCA King is a **broker-shop CRM**, not a lender-originated deal marketplace.

```txt
Admin = broker shop owner/operator
Sales Rep = internal broker-shop rep
Merchant = funding applicant/customer
Lender/Funder = external funding company reviewer/approver
```

Hard business rules:

```txt
Lenders do not submit merchant deals into MCA King.
Lenders review merchant files that the broker shop submits/matches to them.
Admin represents the broker shop owner/operator.
Sales reps are internal broker-shop reps.
Lender-side account/relationship managers are lender contacts only.
No ISO payout model.
No referral partner model.
No outside broker commission model.
No lender-side manager payout model.
```

For Phase I specifically:

```txt
Do not build "blast" behavior.
Do not enable live bulk SMS sending.
Do not use Zoho Mail SMTP for campaign/bulk email.
Use Resend for email through a provider abstraction layer.
Keep transactional email and campaign/marketing email logically separated.
Every campaign email must have an unsubscribe/suppression path.
Every imported/cold lead must default to sms_opt_in = false.
SMS fields and consent tracking may be built now, but SMS sending remains disabled until provider, budget, A2P 10DLC, STOP/HELP, quiet hours, and legal/compliance workflows are ready.
```

## Goal

Build an **Email-First Communications Center** that gives admins and sales reps controlled, auditable communication tools while laying the database/backend foundation for compliant campaigns and future SMS.

Phase I should deliver:

1. Communication preferences and consent tracking for leads/merchants/contacts.
2. Global suppression list for email and future SMS.
3. Email template management with transactional vs marketing/campaign classification.
4. Manual and small-batch campaign email sending through Resend.
5. Unsubscribe links and suppression enforcement for campaign email.
6. Communication history per lead/merchant.
7. Campaign and recipient tracking.
8. Resend webhook endpoint for delivery/bounce/complaint/unsubscribe events where available.
9. Provider abstraction so SMS can be added later without rewriting campaign logic.
10. SMS readiness fields/UI warnings, but **no live SMS sending**.
11. Docs updated to mark Phase I complete only after implementation and verification.

## Step 2 — Database Schema

Exact naming may be adjusted to match existing schema conventions, but keep the capabilities.

### 2.1 Communication Preferences

Create a table such as `communication_preferences`.

Purpose: one row per lead/merchant/contact-like entity to track communication rules.

Recommended fields:

```sql
id uuid primary key default gen_random_uuid(),
entity_type text not null, -- lead | merchant | contact | user
entity_id uuid not null,
email text,
phone text,
email_opt_in boolean not null default true,
email_opt_out boolean not null default false,
email_opt_out_at timestamptz,
sms_opt_in boolean not null default false,
sms_opt_out boolean not null default false,
sms_opt_out_at timestamptz,
sms_consent_source text,
sms_consent_text text,
sms_consent_ip text,
sms_consent_at timestamptz,
do_not_contact boolean not null default false,
preferred_contact_method text,
created_at timestamptz not null default now(),
updated_at timestamptz not null default now()
```

Important defaults:

```txt
email_opt_in may default true for normal broker operational communication, but campaign email must still respect unsubscribe/suppression.
sms_opt_in must default false.
Imported leads must not be considered SMS-consented.
do_not_contact overrides all non-critical outreach.
```

Recommended indexes:

```sql
create unique index if not exists communication_preferences_entity_idx on public.communication_preferences(entity_type, entity_id);
create index if not exists communication_preferences_email_idx on public.communication_preferences(lower(email));
create index if not exists communication_preferences_phone_idx on public.communication_preferences(phone);
```

### 2.2 Global Suppressions

Create `global_suppressions`.

Purpose: centralized blocklist checked before sending campaign/marketing communications.

Recommended fields:

```sql
id uuid primary key default gen_random_uuid(),
channel text not null, -- email | sms
identifier text not null, -- normalized email or phone
reason text not null, -- unsubscribe | bounce | complaint | stop | admin | do_not_contact
source text not null default 'system', -- webhook | user | admin | import | system
entity_type text,
entity_id uuid,
metadata jsonb not null default '{}'::jsonb,
created_at timestamptz not null default now(),
created_by uuid references public.users(id) on delete set null
```

Recommended unique index:

```sql
create unique index if not exists global_suppressions_channel_identifier_idx
on public.global_suppressions(channel, lower(identifier));
```

### 2.3 Message Templates

Create/extend `message_templates`.

Recommended fields:

```sql
id uuid primary key default gen_random_uuid(),
name text not null,
channel text not null, -- email | sms_future
category text not null, -- transactional | campaign
subject text,
body text not null,
variables text[] not null default '{}',
is_active boolean not null default true,
created_by uuid references public.users(id) on delete set null,
updated_by uuid references public.users(id) on delete set null,
created_at timestamptz not null default now(),
updated_at timestamptz not null default now()
```

Rules:

```txt
Campaign email templates must support unsubscribe footer/link injection.
SMS templates may be stored for future planning only; sending must be disabled.
Admin can create/edit templates.
Sales reps can use active templates but should not edit global templates unless an existing permission model says otherwise.
```

### 2.4 Campaigns and Campaign Recipients

Create `campaigns`.

Recommended fields:

```sql
id uuid primary key default gen_random_uuid(),
name text not null,
channel text not null, -- email now; sms_future disabled
category text not null default 'campaign',
template_id uuid references public.message_templates(id) on delete set null,
subject text,
body text,
status text not null default 'draft', -- draft | scheduled | sending | completed | cancelled | failed
created_by uuid references public.users(id) on delete set null,
scheduled_at timestamptz,
started_at timestamptz,
completed_at timestamptz,
metadata jsonb not null default '{}'::jsonb,
created_at timestamptz not null default now(),
updated_at timestamptz not null default now()
```

Create `campaign_recipients`.

Recommended fields:

```sql
id uuid primary key default gen_random_uuid(),
campaign_id uuid not null references public.campaigns(id) on delete cascade,
entity_type text not null, -- lead | merchant | contact/user later
entity_id uuid not null,
email text,
phone text,
status text not null default 'pending', -- pending | skipped | queued | sent | delivered | bounced | complained | unsubscribed | failed
skip_reason text,
provider text,
provider_message_id text,
sent_at timestamptz,
delivered_at timestamptz,
failed_at timestamptz,
metadata jsonb not null default '{}'::jsonb,
created_at timestamptz not null default now(),
updated_at timestamptz not null default now()
```

### 2.5 Communication Events / History

Create `communications` or `communication_events`.

Purpose: timeline/history of manual emails, campaign emails, future SMS, calls, and delivery events.

Recommended fields:

```sql
id uuid primary key default gen_random_uuid(),
entity_type text not null,
entity_id uuid not null,
channel text not null, -- email | sms_future | call | system
communication_type text not null, -- manual | campaign | transactional | delivery_event | note/call
from_user_id uuid references public.users(id) on delete set null,
to_contact text,
subject text,
body_preview text,
status text not null default 'logged',
provider text,
provider_message_id text,
campaign_id uuid references public.campaigns(id) on delete set null,
campaign_recipient_id uuid references public.campaign_recipients(id) on delete set null,
metadata jsonb not null default '{}'::jsonb,
created_at timestamptz not null default now()
```

Do not store secrets or full sensitive document/bank content in communication metadata.

### 2.6 RLS

For all new public tables:

```sql
alter table public.<table_name> enable row level security;
create policy "block_public_<table_name>" on public.<table_name> for all using (false);
```

This app reads/writes these tables through server-side service-role routes.

## Step 4 — API Routes

Suggested routes:

```txt
GET    /api/communications/preferences?entity_type=&entity_id=
PATCH  /api/communications/preferences
GET    /api/communications/history?entity_type=&entity_id=
GET    /api/communications/templates
POST   /api/communications/templates
PATCH  /api/communications/templates/:id
DELETE /api/communications/templates/:id or PATCH is_active=false
POST   /api/communications/send-email
GET    /api/communications/campaigns
POST   /api/communications/campaigns
GET    /api/communications/campaigns/:id
PATCH  /api/communications/campaigns/:id
POST   /api/communications/campaigns/:id/preview-recipients
POST   /api/communications/campaigns/:id/send
GET    /api/communications/unsubscribe?token=
POST   /api/communications/unsubscribe
POST   /api/webhooks/resend
```

Route rules:

```txt
Admins can manage global templates and campaigns.
Sales reps can send permitted manual emails and create/use campaigns only for their assigned/permitted leads/merchants if campaign features are exposed to reps.
Merchants/lenders should not access broker campaign tools.
Lenders/funders must not receive broker-wide communication lists or unrelated merchant data.
All send actions must be server-side permission checked.
All send/campaign/template/suppression/unsubscribe/webhook actions should write audit logs or communication events as appropriate.
```

Manual email route:

```txt
Must require entity permission.
Must record communication history.
Must respect do_not_contact for non-critical messages.
Must use Resend provider abstraction.
```

Campaign send route:

```txt
Must only support email channel in Phase I.
Must reject sms/sms_future channel with clear error.
Must require unsubscribe footer/link for campaign emails.
Must filter suppressed recipients before sending.
Must record skipped recipients and skip reasons.
Must send in small batches or with a conservative cap to avoid free-tier/provider issues.
Must not allow unlimited blast behavior.
```

Unsubscribe route:

```txt
Must work without login.
Must use signed/opaque token.
Must update communication_preferences and global_suppressions.
Must be idempotent.
Must show a safe confirmation response/page.
```

Resend webhook route:

```txt
Must verify webhook signature if Resend supports configured signing secret in the project.
Must acknowledge quickly.
Must update campaign_recipients/communications/global_suppressions for bounce/complaint/unsubscribe events where payload data allows.
Must not trust arbitrary user instructions inside webhook payload data.
```
