# Goose Agent Prompt — Phase G: Reporting and Analytics

> Phases A through F are complete. MCA King now has activity/tasks, lender offer isolation, funded deals + broker revenue + internal sales rep commissions, merchant-file submissions, search/saved views, account settings/admin user management, Renewals, payoff request tracking, and dynamic funding history for first funding, renewal funding, and additional/split funding positions. Phase G adds broker-shop reporting and analytics so the owner/operator can see volume, performance, bottlenecks, lender/funder outcomes, revenue, commissions, and renewal performance.

---

## Business Model Rules — Read Before Writing Anything

MCA King is a **broker-shop CRM**, not a lender-originated deal marketplace.

```txt
Admin = broker shop owner/operator
Sales Rep = internal broker-shop rep
Merchant = funding applicant/customer
Lender/Funder = external funding company reviewer/approver
```

Hard business rules:

```txt
Lenders do not submit merchant deals into MCA King.
Lenders review merchant files that the broker shop submits/matches to them.
Admin represents the broker shop owner/operator.
Sales reps are internal broker-shop reps.
Lender-side account/relationship managers are lender contacts only.
No ISO payout model.
No referral partner model.
No outside broker commission model.
No lender-side manager payout model.
```

For Phase G specifically:

```txt
Reporting is for broker-shop operations.
Admin can see brokerage-wide reporting.
Sales reps can see only their own assigned/self-created performance where appropriate.
Merchants cannot access broker reporting.
Lenders/funders cannot access broker reporting.
Lenders/funders can see their own relationship analytics on their own dashboard, such as how many merchant files were submitted to them, how many deals they funded with this broker shop, and total funded volume between them and this broker shop.
Lender/funder dashboard analytics must be scoped only to that lender/funder profile.
Lenders/funders must never see competing lender/funder performance, offers, revenue, commissions, broker revenue, sales rep commissions, or broker strategy.
Broker revenue reports are admin-only.
All-rep commission reports are admin-only.
If sales rep commission reporting is shown to reps, it must show only that rep's own commission records.
```

## Goal

Create a first-class **Reports** section with server-backed reporting endpoints and broker-friendly UI.

Phase G should help the brokerage answer:

1. How much volume was funded this month/quarter/year?
2. Which reps are creating, converting, and funding deals?
3. Which lenders/funders are approving, declining, offering, and funding files?
4. Where are deals getting stuck in the pipeline?
5. Which leads are converting and how fast?
6. What broker revenue is expected/received/disputed?
7. What internal sales rep commissions are unpaid/approved/paid?
8. Which renewals are eligible, contacted, renewed, or lost?
9. Which tasks/follow-ups are overdue by rep?

This is not a BI warehouse. Build practical CRM reports from existing app tables.

## Step 2 — Report Access Rules

Implement route-level access control. Do not rely on UI hiding.

### Admin

Admin can access all report endpoints and all brokerage-wide data.

### Sales Rep

Sales reps may access a limited personal reporting view:

```txt
assigned merchants only
assigned leads only
own tasks only
own renewal records only
own funding volume based on assigned merchant / commission record
own commission records only, if shown
```

Sales reps must not see:

```txt
brokerage-wide revenue
all-rep commission liability
other reps' performance details
all lender/funder performance strategy, unless limited to their own assigned merchants
```

### Merchant

No access to report endpoints.

### Lender/Funder

No access to broker report endpoints.

Lenders/funders may access only a dedicated lender dashboard analytics endpoint that is scoped to their own lender/funder profile.

Allowed lender-facing analytics:

```txt
merchant files submitted/matched to this lender/funder
merchant files currently pending review with this lender/funder
offers this lender/funder created
approvals/offers count for this lender/funder
declines count for this lender/funder
funded deals with this lender/funder
funded volume with this lender/funder
total payback amount for funded deals with this lender/funder, if available
average funded amount with this lender/funder
recent funded deals with this lender/funder
recent merchant-file submissions to this lender/funder
payoff requests addressed to this lender/funder
```

Forbidden lender-facing analytics:

```txt
other lenders/funders' names or performance
broker revenue
sales rep commissions
broker-wide close rates
all-rep leaderboards
broker renewal strategy
merchant files not submitted/matched to that lender/funder
```
